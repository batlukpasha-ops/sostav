# Dating Service MVP

Это небольшой учебный backend-проект на Python.

Я сделал его, чтобы разобраться, как работает простой API-сервис:

- как сервер принимает запросы;
- как данные проверяются;
- как Python подключается к PostgreSQL;
- как выполняются SQL-запросы;
- как данные возвращаются обратно в JSON.


## Что умеет проект

В проекте можно:

- создать пользователя;
- получить список пользователей;
- получить одного пользователя;
- создать профиль пользователя;
- получить профиль пользователя;
- поставить лайк от одного пользователя другому;
- автоматически создать match, если лайк взаимный;
- получить matches пользователя.

## Какие технологии используются

- Python
- FastAPI
- PostgreSQL
- psycopg
- Pydantic
- обычные SQL-запросы

## Что делает каждый файл

### main.py

Это главный файл проекта.

В нем находятся все API-запросы:

- `POST /users`
- `GET /users`
- `GET /users/{user_id}`
- `POST /profiles`
- `GET /profiles/{user_id}`
- `POST /likes`
- `GET /matches/{user_id}`

Также здесь написана основная логика:

- проверить, что пользователь существует;
- не дать пользователю лайкнуть самого себя;
- не дать поставить один и тот же лайк два раза;
- создать match, если два пользователя лайкнули друг друга.

### database.py

Здесь находится подключение к PostgreSQL.

Проект берет настройки из файла `.env` и через библиотеку `psycopg` подключается к базе данных.

### models.py

Здесь находятся Pydantic-модели.

Они нужны, чтобы FastAPI понимал:

- какие данные приходят в запросе;
- какие данные нужно вернуть в ответе;
- какие поля обязательные;
- какие значения считаются неправильными.

Например, возраст пользователя должен быть не меньше 18.

### schema.sql

Этот файл создает таблицы в PostgreSQL:

- `users`
- `profiles`
- `likes`
- `matches`

Также в нем есть простые ограничения:

- email пользователя должен быть уникальным;
- у пользователя может быть только один профиль;
- нельзя лайкнуть самого себя;
- нельзя создать одинаковый match два раза.

### demo.sql

Этот файл добавляет демонстрационные данные:

- 5 пользователей;
- 5 профилей.

### requirements.txt

Здесь список библиотек, которые нужны проекту.

### .env.example

Это пример файла с настройками базы данных.

Для запуска проекта нужно создать файл `.env` и указать там свои настройки PostgreSQL.

## Как работает проект простыми словами

Пример цепочки:

1. Я нажимаю кнопку в Swagger.
2. Swagger отправляет HTTP-запрос на FastAPI.
3. FastAPI вызывает нужную функцию в `main.py`.
4. Pydantic проверяет данные.
5. Python через `psycopg` подключается к PostgreSQL.
6. Через cursor выполняется SQL-запрос.
7. PostgreSQL возвращает данные.
8. FastAPI отправляет ответ в JSON.

Например, при `GET /users` проект делает SQL-запрос:

```sql
SELECT id, name, email, age FROM users ORDER BY id
```

И возвращает список пользователей.

## Как запустить проект

### 1. Открыть проект

Открой папку проекта в PyCharm:

```text
D:\dating-service
```

Внизу открой вкладку `Terminal`.

### 2. Активировать виртуальное окружение

В терминале PyCharm:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если слева появилась надпись `(.venv)`, значит окружение включилось.

### 3. Создать файл .env

Создай файл:

```text
.env
```

Пример содержимого:

```text
DB_HOST=localhost
DB_PORT=5432
DB_NAME=dating_service
DB_USER=postgres
DB_PASSWORD=0000
```

Если у PostgreSQL другой пароль, нужно указать свой пароль.

### 4. Создать базу данных

Если используется PostgreSQL 18 на Windows:

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres
```

Внутри PostgreSQL:

```sql
CREATE DATABASE dating_service;
\q
```

### 5. Создать таблицы

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d dating_service -f schema.sql
```

### 6. Добавить демонстрационные данные

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d dating_service -f demo.sql
```

После этого в базе будет 5 пользователей.

### 7. Запустить сервер

```powershell
uvicorn main:app --reload
```

Если все хорошо, появится строка:

```text
Uvicorn running on http://127.0.0.1:8000
```

### 8. Открыть Swagger

В браузере:

```text
http://127.0.0.1:8000/docs
```

Swagger - это страница для проверки API.

Там можно нажимать `Try it out` и `Execute`.

## Примеры запросов

### GET /users

Получить список пользователей.

```bash
curl http://127.0.0.1:8000/users
```

### POST /users

Создать пользователя.

```json
{
  "name": "Kate",
  "email": "kate@example.com",
  "age": 26
}
```

### GET /users/{user_id}

Получить одного пользователя.

```text
GET /users/1
```

### POST /profiles

Создать профиль.

```json
{
  "user_id": 1,
  "city": "Moscow",
  "bio": "Coffee and walks."
}
```

### GET /profiles/{user_id}

Получить профиль пользователя.

```text
GET /profiles/1
```

### POST /likes

Создать лайк.

```json
{
  "from_user_id": 1,
  "to_user_id": 2
}
```

### GET /matches/{user_id}

Получить matches пользователя.

```text
GET /matches/1
```

## Какие ошибки обрабатываются

### Пользователь не найден

Если пользователя с таким id нет, API вернет ошибку 404:

```json
{
  "detail": "Пользователь не найден"
}
```

### Нельзя лайкнуть самого себя

Если отправить:

```json
{
  "from_user_id": 1,
  "to_user_id": 1
}
```

API вернет ошибку:

```json
{
  "detail": "Нельзя лайкнуть самого себя"
}
```

### Повторный лайк

Если один и тот же пользователь лайкнет другого второй раз, API вернет:

```json
{
  "detail": "Такой лайк уже существует"
}
```

### Email уже существует

Если создать пользователя с email, который уже есть в базе:

```json
{
  "detail": "Пользователь с таким email уже существует"
}
```
